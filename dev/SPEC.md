# Minesweeper Web Game Specification
[簡報位置](https://www.canva.com/design/DAHLVRO1FAE/iO3mL_EdJszsrOzi5D5RYg/edit)

## 1. 專案概述

本專案為一個踩地雷遊戲，採用C語言實現遊戲核心邏輯，並以Python Flask構建Web前端界面。透過 ctypes 調用C語言接口進行遊戲運算與狀態管理。

目標：
- 實現可在瀏覽器中操作的踩地雷遊戲
- 支援五種遊戲狀態與操作機制
- 提供排行榜、分數紀錄與回溯功能
- 使用SQLite儲存比賽結果

## 2. 功能需求

### 2.1 遊戲內容

遊戲板由 x * y 個格子組成，內含固定數量炸彈。玩家必須透過翻開格子與插旗推理出地雷位置。

格子狀態：
- 覆蓋地板
- 覆蓋地板，被插上旗子
- 翻開地板，顯示周圍地雷數值
- 翻開地板，周圍無地雷的空地板
- 翻開地板，地雷地板

### 2.2 操作機制

- 左鍵點擊：
  - 若點擊到地雷，遊戲失敗
  - 若點擊到非地雷，顯示周圍炸彈數量
  - 若該格為空地板，則展開連續空格直到遇到數值格

- 右鍵點擊：
  - 覆蓋地板可插旗或拔旗
  - 點擊已翻開的數值格時，若周圍未插旗位置數量等於該數值，則自動翻開周圍格子

- 遊戲成功條件：
  - 翻開全部非地雷格子
  - 遊戲通關後讓玩家輸入名稱並將分數存入資料庫

- 其他：
  - 每次操作記錄動作歷程（位置、動作類型）
  - 支援返回上一步，撤回最後動作

### 2.3 難度設定

難度資訊由 JSON 檔案（例如 `Setting.json`）獨立管理。

內建難度：
1. 簡單：9 x 9 版面，10% 炸彈比例
2. 中等：16 x 16 版面，15% 炸彈比例
3. 困難：16 x 30 版面，20% 炸彈比例
4. 自訂：玩家設定行數、列數、炸彈比例

### 2.4 遊戲顯示與資訊

- 頂端顯示剩餘未確定地雷數量
- 插旗時剩餘地雷數值遞減

## 3. 資料結構與實作設計

### 3.1 核心邏輯

- C 語言為遊戲運行核心，提供對外接口
- 使用資料結構儲存格子值與遊戲狀態
- 使用 linked list 紀錄操作歷史，以支援返回上一步
- 遊戲開始時以 `malloc` 配置版面與歷程記憶體
- 遊戲結束或進入排行榜前，釋放版面與歷程記憶體

### 3.2 資料庫

- 使用 SQLite 儲存排行榜資料
- 資料欄位：時間、名稱、分數、難度
- 分數計算方式：全部地板數乘上地雷比例（或依專案需求可進一步定義）

## 4. UI 設計與使用流程

### 4.1 主頁面

- 顯示遊戲標題「踩地雷」
- 顯示兩個主要按鈕：開始遊戲、排行榜

### 4.2 難度選擇頁面

- 顯示內建難度選項
- 提供自訂難度輸入欄位
  - 行數
  - 列數
  - 炸彈比例

### 4.3 遊戲頁面

- 左上：返回上一步按鈕
- 中上：顯示當前剩餘炸彈數量
- 右上：退出遊戲按鈕
- 中央：炸彈版面格子視圖

### 4.4 通關與排行榜

- 通關後要求玩家輸入名稱
- 顯示排行榜列表
- 若當前分數進榜，該筆分數需高亮顯示
- 提供返回主頁面功能

## 5. 系統架構

- 前端：Python Flask Web UI
- 核心：C 語言遊戲邏輯
- 介面：ctypes 呼叫 C 函式庫
- 資料庫：SQLite

## 6. 開發與部署

### 6.1 環境需求

- C 編譯器（GCC 或 MSVC）
- Python 3.8+
- Python 與 C 動態庫架構一致（32-bit / 64-bit）

### 6.2 Windows 下編譯示例

- 使用 MinGW 32-bit：

```powershell
gcc -shared -o app/core/game.dll app/core/game.c
```

- 若為 64-bit 編譯器：

```powershell
gcc -m64 -shared -o app/core/game.dll app/core/game.c
```

### 6.3 執行步驟

```powershell
pip install -r requirement.txt
python app/main.py
```

### 6.4 注意事項

- 若因架構不符無法載入 DLL，需使用與 DLL bitness 相符的 Python 版本或重新編譯對應位元版 DLL
- JSON 設定檔需正確放置並包含各難度參數
